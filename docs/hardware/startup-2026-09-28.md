# Original VGA2USB startup — 2026-09-28

This check used the native userspace tool from commit `1a5fba7`. The test host remained
on its running `7.2.5-1-default` kernel. No legacy module was loaded, no EEPROM
was written, and no host restart was requested or performed.

## Build and offline checks on the test host

`ninja test driver firmware-audit` completed successfully: 8 Ruby decoder/rejection
tests, ASan/UBSan bootstrap transfer/failure checks, exact original firmware hash,
and native libusb compilation.

Physical device: original Epiphan `5555:1110`, USB path `1-12.2`, high speed.
Before startup it was USB device 23, `bcdDevice=0000`.

## RAM-only startup

```sh
sudo -n ./build/vga2usb-native --bootstrap --port 1-12.2
```

The tool transferred the identified 65 segments (7736 bytes) in the vendor's
original order, using request A0 and at most 64 bytes per transfer, then released
CPUCS. All writes returned their requested counts. Complete upload image SHA256:
`eb61be5636ab3cc73f1042f432dd9cbc7e47f6cbc561ea3a9abd1106abcebdec`.

A later independent descriptor inspection found USB device 24 on the same physical
path, still `5555:1110`, with `bcdDevice=0102` matching the firmware record.

## Status observation

```sh
sudo -n ./build/vga2usb-native --sync --port 1-12.2
```

The documented C0:B1 request returned exactly 10 bytes:

```text
00 00 00 00 00 00 0b b8 02 00
```

The first BE16 period counter is zero, which the original driver interprets as no
VGA signal. This agrees with the physical source PC being off at the time. Bytes
4..9 retain the unresolved semantics described in [ADC notes](../protocol/adc.md).

This verifies original-model RAM startup and a working native status read. It does
not establish frame capture, pixel accuracy, live display, screenshot capture,
or repeated reconnect behavior. Those checks remain separate.
