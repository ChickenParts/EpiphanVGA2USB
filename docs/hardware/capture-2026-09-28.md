# First physical capture and live mirror, 2026-09-28

Original VGA2USB `5555:1110`, physical USB path `1-12.2`
on the test host. The host remained on its running Linux `7.2.5-1-default` kernel.
Native libusb transport, vendor RAM firmware `0102`, no legacy kernel module.

After the user powered the source PC on, B1 returned
`6f 7d 01 c2 00 f2 0a c6 02 00`: period 28541, total lines 450,
about 70.07 Hz. This uniquely identifies the supported 720×400 text preset.

One large bulk request ended at 1536 bytes. Changing to the vendor's five
row-aligned reads still ended at 1536 bytes. Matching USB chunk sizes alone
therefore did not fix the capture. The original HOME recovery rule was then
implemented: after three incomplete frames, advance vertical phases to the next
height divisor, updating only B4 offsets 18–21 and 25.

The first successful snapshot followed these attempts:

| Vertical phases | Actual wire totals, bytes |
|---:|---|
| 2 | 1536, 3072, 1536 |
| 4 | 434688, 58368, 46080 |
| 5 | 614304 — complete |

The complete wire frame decoded to a 720×400 RGB565 image and an 864015-byte
P6 PPM. Colors, row order and text orientation were inspected from the PNG:

![First physical capture](images/first-capture-2026-09-28.png)

The source shows Phoenix BIOS 3.10.01, an 80386SX at 16 MHz, and its POST
continuation prompt. CMOS checksum, real-time clock and keyboard failures are
visible.

A continuously running native stream was displayed through ffplay full-screen
on the test host's KDE Wayland desktop, using a 4:3 display aspect. A desktop screenshot
was independently inspected and showed the enlarged captured BIOS screen.
This stream initially succeeded at four phases, encountered later incomplete
frames, then recovered to five phases. Bad frames were rejected before PPM output.
An ffplay startup log contained one `Invalid maxval: 0` warning; the displayed
image was valid. The concatenated PPM output has a separate offline boundary check.

Offline checks cover row-aligned read lengths/order, failed B4 and submit paths,
short-frame cancellation, three-failure phase recovery, and continuous PPM frame
boundaries under ASan/UBSan. Both initial firmware/decoder checks and native driver
build passed on the test host before capture. The reviewed milestone `9bb19a2` was then
synchronized to the test host; `ninja test driver firmware-audit` passed there too, including
retained V4→V5 stream recovery and early callbacks during B4 control handling.

Limits: only this physical text mode has been inspected. The 640×480 preset,
source-mode transitions and USB disconnect/reconnect remain unqualified. Recovery conservatively increases phases after three consecutive
incomplete frames; the vendor's longer-term failure-rate and downward tuning are
not yet implemented. No missing useful pixels are accepted.
